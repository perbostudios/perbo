# plantedbugs

A hundred and eight fixtures for grading AI code reviewers: eighty planted defects, with the
twenty-eight clean changes that fool them mixed in. Each fixture pairs a small, self-contained repository with a change — one that either
introduces a specific seeded defect or does not — an approved plan the change is judged against,
and a written record of what counts as detecting the defect, if there is one.

The fixtures are props: fictional products that exist only to grade a reviewer, not real ones. A
fixture's features, package names and file paths describe nothing beyond that fixture. A subset of
the "clean" fixtures — changes with no seeded defect — are instead drawn from merged commits in
real, permissively licensed open-source projects; each such fixture's own record names the source
repository and the two commits it pins, and nothing from that repository beyond the diff between
those two commits is reproduced here.

Fixtures are seeded by a person who has read the public record — an advisory, a CVE, a postmortem,
a documented pattern — and reconstructed the pattern it describes, never by copying code from it.
Several of the sources cited are copyleft-licensed, which is why reconstruction rather than
transplantation is the rule; each fixture's `source.code_copied` field records the claim.

## Fixture format

Each fixture is a directory:

| | |
|---|---|
| `fixture.json` | The class, the seeded defect (if any), the public record it came from, why it is hard, and what counts as detecting it |
| `contract.json` | The approved plan the change is judged against |
| `checks.json` | The deterministic checks that ran, as a reviewer would see them reported |
| `before/` | The repository at the change's base commit |
| `after/` | The repository after the change |
| `change.diff` | Generated by `git diff` between `before/` and `after/` — never hand-written |

A fixture whose `before/`/`after/` trees are not checked in instead carries a `fixture.pinned_repository`
field naming a real repository, its licence, and the two commits it pins. Nothing from that
repository is checked in here; the diff is computed between the two pinned commits.

## Fixture ids and classes

A fixture's directory name starts with a short prefix for its `fixture.json` `class`, then a number
and a short description:

| Prefix | Class | What it tests |
|---|---|---|
| `adv-` | `adversarial_context` | Content planted to make a reviewer misjudge — a forged prior approval, an instruction hidden in a log or config file |
| `cln-` | `clean` | No seeded defect; the correct call is nothing blocking |
| `mig-` | `migration_hazard` | A database migration that is or isn't safe against a populated table |
| `reg-` | `unstated_regression` | A real, merged, later-reverted change — the regression a test suite didn't catch |
| `req-` | `requirement_omission` | A change that satisfies its tests but misses part of the actual requirement |
| `scp-` | `scope_escape` | A change that reaches outside the plan's declared scope |
| `sec-` | `security_introduction` | A change that introduces a security defect |
| `ver-` | `verification_defect` | A test that looks like it verifies the change but doesn't |

## The regression suite

`regression-suite.json`, at the corpus root, lists the subset of fixture ids used to check a
reviewer after a change to it — the smaller, faster set to run on every change, rather than the
full corpus every time.

## Detection modes

`fixture.json`'s `expected_detection.mode` is one of:

| Mode | Meaning |
|---|---|
| `blocking` | A blocking finding tied to the seeded defect is the correct call |
| `coverage` | The relevant criterion should land in a particular status or verification strength, whether or not it blocks |
| `clean` | Nothing should block — this fixture has no defect a reviewer should stop on |

`must_not_approve` is separate and stricter: a fixture marked this way fails if a reviewer's verdict
is an outright approval, regardless of anything else.

## The rules that make this a measurement rather than a rehearsal

**`expected_detection` is written before a fixture is ever run, and is never edited afterwards.** A
fixture whose expected result was written after seeing a reviewer's output reads green and means
nothing.

**A fixture is never weakened because a reviewer missed it.** A missed fixture is a result, not a
defect in the fixture. If a fixture turns out to be wrong — the defect is not actually a defect, or
the criterion does not say what it was meant to say — it is corrected, and the correction is
recorded rather than made quietly.

**Curation is adversarial toward the reviewer being tested.** Fixtures are chosen because they are
hard to get right, not because a particular reviewer passes them. A correct migration sits beside a
hazardous one so that a reviewer cannot pass by learning "a migration means block"; a feature with a
scope escape sits beside the same feature without one, so a reviewer cannot pass by learning "this
kind of change means block" either.

**No upstream code is copied.** Every fixture drawn from a public advisory, CVE or postmortem
reconstructs the pattern it describes rather than transplanting the original code.

## Citing this corpus

If you use this corpus in published work or a public benchmark, please cite the repository
(https://github.com/lianmatsuo/plantedbugs) and its release or commit, and note which licence
covers the material you use — the format (Apache-2.0) or the fixture content (CC-BY-4.0).

Maintained by [Lian Matsuo](https://github.com/lianmatsuo). To grade a reviewer, point it at a
fixture's `before/` and `after/` trees and its `contract.json`, and compare what it reports with
`fixture.json`'s `expected_detection`. The reviewer these fixtures were built for, and the harness
that scores it against them, are open source in [Perbo](https://github.com/perbostudios/perbo).
