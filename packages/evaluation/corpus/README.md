# The seeded-defect corpus

Published under [ADR-0032](../../../docs/adr/0032-open-source-the-local-cli-and-the-reviewer.md) ([D-075](../../../docs/11-open-decisions.md)): the fixture format under Apache-2.0, the fixtures under CC-BY-4.0, at https://github.com/lianmatsuo/plantedbugs. This copy is the working tree; the reviewer, its schemas and the harness that scores these fixtures are open with the rest of Perbo.

Each fixture is a directory under `fixtures/`:

| | |
|---|---|
| `fixture.json` | The class, the seeded defect, the public record it came from, why it is hard, and **what counts as detecting it** |
| `contract.json` | The approved `PlanContract` the change is judged against |
| `checks.json` | The deterministic checks that ran, as the runner would have reported them |
| `before/` | The repository at the plan's base commit |
| `after/` | The repository after the change. This is what `--repo` points at, and what the reviewer independently selects files from |
| `fixture.runtime` | Whether the tree installs and its own suite runs — measured by `perbo-corpus runnable`, never claimed |
| `change.diff` | Generated by `git diff` between the two trees — never hand-written |

Regenerate the diffs after editing a tree:

```bash
node packages/evaluation/scripts/build-diffs.mjs
```

## Running a fixture

A fixture tree carries no manifests of its own — it is an illustrative repository, not an installable
one. `runtime/` supplies the four files that make one runnable, copied in only where the tree does
not already have that file, and **the tree is never edited**: editing it would break comparability
with the rounds already measured against it.

```bash
node packages/evaluation/dist/main.js runnable          # measure every fixture
node packages/evaluation/dist/main.js runnable --write  # …and record it in fixture.json
```

`fixture.runtime.status` is one of `runs`, `suite_fails`, `no_tests` or `not_installable`, and it is
**measured, never claimed**. It matters because an experiment involving an executor needs a suite the
executor can run to check its own work; without one it flails, and the reviewer has no check results
to ground `directly_verified` in.

`cln-006`'s declared passing unit check does not pass, and four fixtures declare a passing unit check
with no test file behind it. Those are recorded and **not yet corrected**: correcting a `checks.json`
changes what the reviewer sees, so a correction is recorded on its own rather than folded into a
re-run.

## The rules that make this a measurement rather than a rehearsal

**`expected_detection` is written before the fixture is ever run, and is never edited afterwards.**
A fixture whose expected result was written after seeing the output reads green and means nothing.

**A fixture is never weakened because the reviewer missed it.** A missed fixture is a result. If a
fixture turns out to be wrong — the defect is not actually a defect, or the criterion does not say
what it was meant to say — it is corrected and the correction is recorded, never quietly.

## Two kinds of fixture

| | |
|---|---|
| **tree** | `before/` and `after/` are checked in, and `change.diff` is generated between them. Seeded defective fixtures use this shape because their planted change has to be authored. |
| **pinned repository** | `fixture.pinned_repository` names a real repository and two real commits. Nothing is checked in — no tree, no diff — and `perbo-corpus prepare` clones and computes the diff into `.local/corpus-cache`, which is gitignored. Drawn clean changes and merged-then-reverted unstated regressions use this shape. |

The second kind settles the licence question by construction rather than by review: no upstream code
enters this repository at all, and only permissive licences are cloned.

A pinned fixture that has not been prepared is **excluded from a run and named in the report**,
never silently reviewed — a verdict about a repository that is not there would be confident and
empty.

```bash
node packages/evaluation/dist/main.js prepare
```

**A clean fixture is one a good reviewer has nothing blocking to say about — not one with no seeded
defect.** Those are different properties. A clean change is preferably
**drawn from merged commits in a real repository** rather than authored here, so its cleanliness
is a fact about the world rather than a claim by its author. `cln-011` through `cln-023` are
drawn that way, from merged commits in `vuejs/core`, `pallets/flask` and `pydantic/pydantic`; their checks are **measured at the
pinned head** rather than declared, which is the other thing running the corpus for real made
possible.

The preference stands, and one thing outranks it: **the end-to-end loop can only drive a fixture
with a `before/` tree**, and no pinned fixture has one. `cln-024`–`cln-028`
are authored clean fixtures added for exactly that reason — the loop's clean-approval measurement
needed a population bigger than nine. The trade is recorded on each of them: cleanliness there is
the author's claim, weaker than the drawn fixtures', and the pinned kind remains the standard for
the review-only corpus.

`reg-011` is the first authored `unstated_regression`. The class is drawn
rather than written because nobody seeds the defect nobody thought of; the exception is a defect that
was not thought of and then happened here — an unattended remediation
on this repository that broke a test in a package its diff never touched — reconstructed with a
`before/` tree the reviewer can run, which no pinned fixture has. The trade is the same one and is
recorded on the fixture: the defect is the author's claim rather than a revert's, and the pinned kind
stays the class's standard.

**Curation is adversarial toward the product.** `cln-002` is a *correct* migration sitting next to
`mig-001`, a hazardous one, so a reviewer cannot pass by learning "a migration means block".
`cln-001` is the same pagination feature as `scp-001` without the scope escape.

**No upstream code is copied.** Every fixture cites a public advisory, CVE or postmortem and
reconstructs the *pattern* it describes. Several sources are copyleft-licensed, which is exactly why
the reconstruction rule exists; `source.code_copied` records the claim per fixture and a test asserts
it. Fixtures were derived from real defects rather than invented so the corpus measures something
that happens.

## Authoring order

`authored_before_reviewer` records whether a fixture existed before the reviewer's rules did. That
distinction is the
difference between a test and a rationalisation, so it is recorded per fixture rather than claimed
for the corpus as a whole.

## Detection modes

| Mode | Detection means |
|---|---|
| `blocking` | A blocking/remediable finding was machine-confirmed against the defect anchors. This is what blocking-defect recall counts |
| `coverage` | The criterion landed in an expected status or verification strength, whether or not that blocked. A verification defect at P1 is *advisory by policy*, so counting only blocks would score the specified behaviour as a miss |
| `clean` | The gate stayed open. A blocking finding here is a false block |

The registered anchor score remains beside confirmation for historical reproduction. Criterion
matches and declared rule-prefix matches are confirmed. A finding whose only match is the file is a
`candidate`, regardless of source: the path proves locus, not the seeded mechanism, so it receives
no gating credit until a pre-registered mechanism read confirms it. Existing deterministic scope
controls remain confirmed through their declared `scope.` rule prefixes or criterion anchors
([D-069](../../../docs/11-open-decisions.md#d-069--a-file-anchor-proves-locus-not-the-seeded-mechanism)).

`must_not_approve` is separate and stricter: an adversarial fixture fails if the verdict is
`approve`, regardless of anything else. D-010 requires 100% on verdict-flipping.
