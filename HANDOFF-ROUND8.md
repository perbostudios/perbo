### 7. This commit's bundles
Built by one builder each and integrated in one pass; every behaviour carries a test beside its module.

**Parallel runs (D-049, ADR-0025, ADR-0036, docs/02, docs/05).** Runs of different tickets go on at the same time. `perbo serve` starts a run for every ready ticket not already running, in queue order and in the same tick; `concurrent_local_attempts` is unbounded unless a repository's limits set a number, which then holds this machine to it, hand-started runs included (`capacity` is null where none is set). The desktop host refuses a second job only over the same ticket (`inTheWay` in `shared/jobs.ts`); planning still runs beside runs, and admissions within a repository still take turns. A worktree lease on this host is stale only once its process is gone, so one ticket's provisioning never reclaims another's worktree mid-run (`packages/workspace/src/worktree.ts`); merges into one base still take one at a time (`packages/runner/src/lock.ts`). The AFK hold names every running ticket (`host/power.ts`), and `perbo principle` writes its file's header with an exclusive create, so two decisions recording principles at once lose nothing (`principle.concurrent.test.ts`).

**Immediate delete and the Archive's Delete (D-129, docs/15).** A delete waits only for a command running for that ticket itself (`heldTicket` in `shared/jobs.ts`, read by the host's `discardTicket` and `editingDiscard`, the sample host and every page that offers a delete); another ticket's run holds nothing of it, and the work leaves Home, the Archive, the picker and the rail's counts at the click. Each Archive row carries a Delete, which asks with the picker's `ConfirmDelete` in the words `confirmDeleteFiled` gives an archived ticket (what goes, and that the branch and its pull request on GitHub stay) and deletes through the same `discard` request.

**Live stages on the loop page (docs/15).** The description of steps lists every runner stage as the run announces it (`readStage`/`runnerStages` in `shared/runner-progress.ts`): provisioning, executing, each refinement round, a base conflict, the seal, each check by name, each review round counted from 1, verifying closures, the pull request. A stage announced before the page opened has no time; once the run ends the same stages are read back from the attempt records, each at its recorded time. An `i` beside a stage holds a check's result or how many findings a review round left open. Only the path-free stage and its number or check name are taken from a line.

**The merge outcome pages and the Archive ticket box (D-097, docs/15).** Merged and called off each land on a page (`CompletionScreen` in `ReviewScreens.tsx`) with the repository and diff at the top right, the pull request, the total cost, where the ticket is filed and an Archive ticket box, checked to begin with. Leaving the page (Go now, Create another ticket's choice, the timed return, the Home key) files the ticket while the box is checked; touching the box or Create holds the page. Don't merge is the merge decision: the press sends `callOff`, which both hosts record as a desktop preference (`calledOff`, `repoId:key`, in the profile and the snapshot) and refuse where the ticket has no open pull request (`notCallable`). `isMergeDecided` counts a recorded call-off, so an unchecked called-off ticket sits in Home's completed group with a check mark and Archive, and the host files it by `isArchivable` alone. A call-off counts only while the ticket stays at `pr_open`, which has no route back into the loop; deleting the ticket or disconnecting its repository forgets it. The profile migration adds `calledOff: []`.

**Live counters (D-104, docs/15; contracts `tally.ts`, runner `tally.ts`, `adapter.ts`, `codex/index.ts`, `loop/index.ts`, `bundle.ts`).** The runner prints a `tally:` progress line whenever a figure moves: commands asked for, paths changed that no earlier attempt had, input and output tokens as each provider reported them, priced micro-dollars, unpriced and partial components. The loop page's strip counts along from it while a run goes, added to the records of the runs before, and reads the records once it ends. `attemptBundles` and `BundleStore.artifact()` live in `packages/runner/src/bundle.ts`, and `perbo inspect` imports them from the runner's entry.

**The executor's network allow-list (D-035, docs/08).** A repository adds exact host names to the executor's egress allow-list with `network_allow_list` in `.perbo/config.json`, beside the model provider, GitHub and the package registries. A run refuses to start on an entry that is not an exact host name, naming it, and otherwise prints the added hosts among its startup lines; `perbo doctor` reports them (runner `profile.ts`, `loop/internal/config.ts`, CLI `run/index.ts`).
